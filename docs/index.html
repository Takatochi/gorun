gorun — Go's M:N Concurrency Model for Modern C++

Ultra-fast stackful green threads (~64.7 ns user-space context switch), zero-allocation stack-to-stack Channel<T>, select(...) multiplexing, cascading gorun::Context, GORUN_DEFER, and RAII structured concurrency (gorun::Scope).

Quick Start & Installation

Because gorun is 100% header-only with zero external dependencies, add it directly via CMake FetchContent:

include(FetchContent)

FetchContent_Declare(
    gorun
    GIT_REPOSITORY https://github.com/Takatochi/gorun.git
    GIT_TAG        v0.2.0-alpha
)
FetchContent_MakeAvailable(gorun)

add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE gorun::gorun)

Minimal Example (Works Directly in int main())

#include <iostream>
#include "gorun/gorun.hpp"

int main() {
    gorun::Channel<int> ch(4);

    gorun::go([&]() {
        GORUN_DEFER { ch.close(); }; // Guaranteed LIFO cleanup on scope exit
        ch.send(42);
    });

    if (auto v = ch.recv()) {
        std::cout << "Received from green routine: " << *v << "\n";
    }
}

Core Architectural Invariants

1. Zero OS-Thread Blocking

Channel<T>, Mutex, CondVar, WaitGroup, Semaphore, RwMutex, and sleep_for never block the underlying std::jthread worker. They park the green routine in ~65 ns and immediately execute the next runnable routine.

2. Stack Stability Invariant

Unlike Go (which reallocates and copies 2 KB stacks when they grow, invalidating pointers), gorun allocates fixed 128 KB virtual stacks with a 4 KB hardware PAGE_NOACCESS Guard Page. Stack addresses never move.

3. Structured Concurrency by Default

gorun::Scope and gorun::TaskGroup automatically attach any inner gorun::go([&]{ ... }) calls (including transitively nested ones) and join them in ~Scope(), preventing dangling [&] references.

4. Deterministic Exception & Pointer Safety

Uncaught exceptions inside routines are captured into std::exception_ptr, trigger std::stop_token sibling cancellation, and rethrow on wait() / get().

4-Layer Pointer Safety & Advanced Memory Allocation

How gorun guarantees zero lost pointers, zero dangling stack pointers, and zero memory leaks across 16+ OS worker threads (verified by [TEST 20] auditing 10,500 heap objects):

Pointer Category What Fails in Naive Runtimes / Go How gorun Guarantees Safety
1. Raw Stack Pointers (&local_var) Go copies & relocates growing 2 KB stacks, breaking interior pointers. Fixed Virtual Stacks (StackPool): 128 KB + 4 KB Guard Page. Stack addresses never move during a routine's lifetime.
2. Routine* in run_next_ Unlocked run_next_ slots can strand routines when a worker runs a long task. Stealable run_next_ inside WorkStealingDeque: Idle thieves steal directly from both the FIFO ring buffer and run_next_.
3. thread_local on -O3 GCC/Clang cache thread_local pointers in registers (%rbx) across function calls. Compiler TLS Barrier: noinline + atomic_signal_fence on context_switch forces fresh %gs/%fs reads after migration.
4. Closure Smart Pointers (shared_ptr) Pooled fibers retain their last std::function closure in the pool, leaking memory. Immediate Reset: routine_trampoline executes r->task = nullptr; before recycling the routine into local_free_routines_.

Large-Scale Memory Patterns (From examples/05_memory_arenas_and_pointers.cpp)

Pattern 1: Zero-Copy std::unique_ptr<PacketSlab> Pipeline + Per-Routine Bump Arena:

// 1. Move-only 256-byte PacketSlab transferred across 3 channel stages with ZERO copies:
gorun::Channel<std::unique_ptr<PacketSlab>> ingest_ch(16);

gorun::go([&]() {
    GORUN_DEFER { ingest_ch.close(); };
    for (uint64_t id = 1; id <= 200; ++id) {
        auto slab = std::make_unique<PacketSlab>(id);
        // Allocated once on heap; pointer ownership moves directly stack-to-stack!
        ingest_ch.send(std::move(slab));
    }
});

// 2. Per-Routine Linear Bump Arena with O(1) bulk deallocation on routine exit:
gorun::go([&]() {
    LinearArena arena(16 * 1024); // 16 KB contiguous arena
    GORUN_DEFER { arena.reset(); }; // Instant O(1) cleanup even on exception!

    HttpHeaderNode* head = nullptr;
    for (int h = 0; h < 50; ++h) {
        head = arena.create<HttpHeaderNode>(h, "X-Gorun", "Zero-Copy", head);
    }
    gorun::yield(); // Migrates to another OS core — all arena pointers remain 100% valid!
});

// 3. Parent Stack-Frame Pointers Shared with 32 Child Routines inside gorun::Scope:
gorun::go([]() {
    std::array<StackWorkNode, 32> stack_nodes{}; // Lives on parent routine's 128 KB stack!
    {
        gorun::Scope inner_scope;
        for (int i = 0; i < 32; ++i) {
            StackWorkNode* raw_stack_ptr = &stack_nodes[i];
            gorun::go([raw_stack_ptr]() {
                gorun::yield();
                raw_stack_ptr->computed_result += 10; // Safe! Parent is parked at ~inner_scope()
            });
        }
    } // ~inner_scope() joins all 32 children before stack_nodes goes out of scope!
});

Complete Tool-by-Tool Reference & "The One-Way Rules"

1. gorun::go(...), gorun::Scope, and gorun::TaskGroup

DO (The One Way)

Always declare gorun::Scope scope; before capturing local stack variables by reference [&] in gorun::go([&]{ ... }). For detached background tasks without a Scope, capture by value [x] or std::shared_ptr.

DON'T (Forbidden)

NEVER capture local stack variables by reference [&] in a detached gorun::go(...) that outlives the enclosing function frame.

// [WRONG]: Detached routine captures local `x` by reference [&] and outlives bad_func()!
void bad_func() {
    int x = 42;
    gorun::go([&]() { std::cout << x; }); // DANGLING REFERENCE!
}

// [CORRECT]: ~Scope() parks the parent routine until all inner go() calls complete!
void good_func() {
    int x = 42;
    gorun::Scope scope;
    gorun::go([&]() { std::cout << x; }); // 100% SAFE!
}

2. gorun::Channel<T> & gorun::select(...)

DO (The One Way)

Always close producer channels with GORUN_DEFER { ch.close(); }; so receivers iterating with while (auto v = ch.recv()) terminate cleanly. Declare channels above gorun::Scope so the channel outlives all routines accessing it.

DON'T (Forbidden)

NEVER destroy a Channel<T> while a detached routine still holds a reference to it. Use std::shared_ptr<Channel<T>> if the channel is shared across detached tasks.

3. gorun::Mutex, RwMutex, CondVar, WaitGroup, Semaphore, Once

DO (The One Way)

Always use gorun::Mutex (with std::lock_guard / std::unique_lock), gorun::RwMutex (with std::shared_lock), and gorun::sleep_for() inside green routines.

DON'T (Forbidden)

NEVER call std::mutex::lock(), std::condition_variable::wait(), or std::this_thread::sleep_for() inside a green routine — doing so blocks the OS kernel worker thread and freezes all other routines queued on that worker!

4. Go-Style Cascading gorun::Context

DO (The One Way)

Pass gorun::Context as the first parameter to request handlers and DB queries. Always pair auto [ctx, cancel] = gorun::with_timeout(parent, 50ms); with GORUN_DEFER { cancel(); }; and await ctx.on_done(...) inside gorun::select(...).

DON'T (Forbidden)

NEVER store mutable unsynchronized raw pointers inside gorun::with_value(ctx, key, val). Store immutable values (std::string, int, std::shared_ptr<const T>) for lock-free reads.

5. GORUN_DEFER { ... }; & gorun::defer(fn)

DO (The One Way)

Use GORUN_DEFER { ... }; for guaranteed LIFO resource cleanup at block exit, and use auto guard = gorun::defer(fn); with guard.dismiss() for database/payment transaction rollbacks.

DON'T (Forbidden)

Remember that in C++, GORUN_DEFER is block-scoped ({ ... }), not function-scoped like Go: placing GORUN_DEFER inside a for loop body runs it at the end of every iteration.

6. gorun::RoutineLocal<T> vs. thread_local

DO (The One Way)

Use gorun::RoutineLocal<T> or gorun::Context for routine-specific state that persists across suspension points.

DON'T (Forbidden)

NEVER cache the address or value of a C++ thread_local variable across a yield(), sleep_for(), Channel, or Mutex operation, because work-stealing may resume the routine on a different OS thread.
